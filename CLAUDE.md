# ataniq

## Commands

- Whole test suite: `make test`. Run it once after a set of related changes is merged, not after every edit.
- `make test-canary` runs the tests of code behind the `ataniq_canary` build tag; `make test` stays untagged. While tagged code exists the whole suite is `make test` and then `make test-canary`. `make test-ownerchannel` runs the tests of code behind the `ataniq_ownerchannel` build tag, alone and together with the canary tag. Neither tagged target runs `./tests/` (the checks of both tags) except in a run that has no package whose build constraint names a tag it sets, so that `go test` never gets an empty list: it runs once, untagged, in `make test`, and its tag checks run `go list` with the tags they need. While code behind the owner channel's tag exists the whole suite is `make test`, `make test-canary` and `make test-ownerchannel`. `make ownerchannel-build` is the one target that builds a binary with that tag alone, only the daemon, into `build/owner/`, for the owner's own trial; no release and no CI job uses it, and it starts nothing. `make scratch-seat-build` is the one target that builds the daemon with both tags, only the daemon, into `build/scratch-seat/`, for the owner's own trial of real scratch leads with the seat gate; no release and no CI job uses it, and it starts nothing. `make canary-build` is the one target that builds binaries with the canary tag alone, for the attended canary run (`qualification/canary/run/README.md`); no release and no CI job uses it. Never run `qualification/canary/run/canary-run.sh` without `--dry` or `--self-test`. `qualification/canary/run/canary-reset.sh` also deletes directories and is run only by the owner's hand, never by an agent; its only agent-safe forms are `--dry` and `--self-test`. Run `qualification/canary/run/canary-prepare.sh` only with `--dry` (or `--self-test`). `ROOT/netcheck.sh` (written by `canary-prepare.sh --pass B`) starts pasta, bubblewrap and a throwaway user unit and makes four unauthenticated requests, and is run only by the owner's hand, never by an agent. `deploy/ai-host/ap14-level1.sh` (AP14 level 1 on an AI host) changes sudo and creates `/etc/ataniq/grants`, and is run only by the owner's hand, as root: an agent runs it only with `--self-test`, never with `--dry` or `--apply`.
- While working on a task, run only the check that covers what you changed.

## Rules

- Branches follow git-flow: `master` (releases, tagged), `develop` (integration), feature branches merged into `develop` with `--no-ff`, `release/<version>` from `develop`, `hotfix/<version>` from `master`. Never commit to `master` or `develop` directly except by merging a branch.
- Every user-visible change gets a changelog fragment, `changelog.d/<section>-<slug>.md`, in the same commit, not an edit of `CHANGELOG.md`. Release flow: `qargi release start <version>` dates the changelog in the release branch's first commit (pass `--allow-empty-notes` when the release's entries are all fragments, since `[Unreleased]` is then empty and the start is refused otherwise); the first fix commit on the release branch folds the fragments into that section with `make changelog-fold ARGS='--into <version>'` (committed through `qargi release fix`, and again after any later fix that adds a fragment), then `make changelog-check` must pass, then `qargi release push`. A hotfix does the same, once it has a fix and its dated section, before its pull request. Entries already under `[Unreleased]` stay there; correcting one is an edit of `CHANGELOG.md`. See `changelog.d/README.md`.
- No private names (hosts, users, home paths, secrets) in files or commit messages.
